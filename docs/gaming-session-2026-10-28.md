## 3. 关键观察

### 3.1 存储：这次没有复现上次的故障

23:20–00:05 的 System 日志中，`disk`(153) / `UASPStor`(129) / `disk`(51) / `Ntfs`(98/140) / `volmgr`(157) 相关事件 **0 条**。上次（10-23）那次是 517 条 153 + 116 条 129，这次干净，说明当时的问题确实挂在 USB 移动硬盘那条链路上，与游戏负载无关。

唯一异常是 23:57:42 一个采样点：磁盘 98.9 %、队列 0.99。紧接着的 23:58:14 与 23:59:16 采样里，commit 从 43.42 涨到 43.98 再回落到 41.97，显存从 11,214 降到 10,350 MiB，温度从 66.3 降到 62.7 °C。形态像**场景切换 / 资源重载**（读盘 + 释放旧资源），不是卡死前兆。

### 3.2 内存长期贴底

- 74 条采样里 **42 条可用内存 < 3 GB**，最低 1.4 GB。
- 但页面文件使用率最高只有 1.3 %（40 GB 页面文件 ≈ 0.53 GB 在用），说明**还没有开始大量换页**，系统靠压缩内存 + 清理缓存撑住了。
- 这时如果同时再开一个大型程序，就会进入换页，表现为整机卡顿——与用户描述的「拖得重启不了」可能有共同机制，但仍需复现验证。

### 3.3 显存长期在 90 % 以上

- 58/74 条采样显存 > 11 GB，峰值 11,365 MiB（92.5 %）。
- 游戏本体 1440p 已经吃掉 10–11 GB；后台 Edge 视频页还要额外占 0.3–0.5 GB。
- 显存不足的表现是贴图糊、偶发大卡顿（跳帧），而不是崩溃；再叠加 40 GB 页面文件挂在 D 盘同一块 SSD 上时会放大 I/O。

### 3.4 温度与功耗健康

平均 68 °C / 163 W，峰值 74.5 °C / 181.8 W，功耗墙 200 W。风扇 45–50 %，仍在低转速区间，说明散热余量充足；没有 `Kernel-Power 41`、没有 `BugCheck 1001`、Minidump 目录为空。

## 4. 建议

1. **内存是第一瓶颈**。这类「前台游戏 + 浏览器 + DSH + Razer/Armoury 常驻」的组合已经吃满 32 GB：想稳，要么减少常驻（关 Edge 多余标签/扩展、退出不用的 Razer/华硕套件），要么加内存到 64 GB。
2. **显存接近上限**，若出现贴图加载卡顿，先把游戏内纹理/显存相关画质降一档，或把后台视频页关掉；这比加内存更立竿见影。
3. **页文件别急着砍**：40 GB 页面文件在峰值提交 44 GB 时是缓冲垫，1.3 % 使用率说明暂时够用，动它收益极小、风险不小。
4. 若再出现「黑屏/卡死」，立刻记录时间点，用 `Get-WinEvent` 拉 23:20–00:05 同类查询即可对照——这次的判据是：有 153/129 → 存储链路；无 153/129 但有高 commit/低可用 → 内存压力；两者都没有 → 另找 GPU/驱动侧证据。
