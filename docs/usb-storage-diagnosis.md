## 6. 关键判断

1. **40–56 MB/s 是 USB 2.0 + BOT 的实际上限**，不是盘的极限。该盘在 USB 3.0 下应达 90–110 MB/s。
2. 当前枚举为 `USBSTOR`（BOT），`UASPStor\Enum` 为空 —— 即使插在"蓝色口"上，链路仍按 USB 2.0 协商，故 **10-23 的崩溃条件（3.0 + UASP）无法在现状下复现**。
3. 5 秒卡顿在 USB 2.0 链路上同样出现过，且与盘内 SMART「最大读延迟 5,035 ms」吻合 → **停顿来源在盘体内部**（弱扇区重试或停转唤醒），不是 USB 带宽问题。
4. 描述符层面证据：设备 `CompatibleIDs` 为 `USB\Class_08&SubClass_06&Prot_50`（Prot 0x50 = Bulk-Only Transport），UASP 应为 `Prot_62` —— 盒子当前**以 BOT 身份上报**，与「链路只跑 High Speed」自洽。主板后置蓝色 USB 3.0 口 + 原装线仍如此 → SuperSpeed 通道未建立，最可能是盒子的 SS 通道在 10-23 的 116 次 `UASPStor` 重置后降级（线材 SS 差分对损坏为次要可能）。
5. 10-23 的 116 次 `UASPStor` 重置 + 32 次 `disk` 51 分页错误 + 1 次 `Ntfs` 140（写日志刷新失败，有数据损坏风险）→ UASP 链路在高负载下不可靠。

## 7. 待办与下一步

- [ ] 换一根确认支持 USB 3.0 的短线（接头内可见额外 5 个触点），重新插入后置蓝色口，确认枚举变回 `UASPStor`
- [ ] 用另一个已知 USB 3.0 设备（U 盘/硬盘盒）在同一口测速：>100 MB/s 说明口正常、问题在盘/线
- [ ] 3.0 链路恢复后，在游戏负载下开 `.\scripts\usb-diag.cmd watch -Seconds 1800`，观察 `129/153` 是否复现
